NV-33 / NV-34 ETag and the If-Match parser. The transition route accepts If-Match only in
the form /^"v(\d+)"$/ (src/routes/requestRoutes.js, versionFromIfMatch, line 29). The GET
emits etagFor(result.version) = "v<version>" (same file, etagFor, line 25; GET handler line
71). One-off check, run against the real readCommand (not a test, nothing kept):

  "v3"      -> expectedVersion 3
  3         -> rejected: PreconditionRequiredError
  W/"v3"    -> rejected: PreconditionRequiredError

So the format the GET emits is accepted, and the two mutated formats would be refused when
a client sent them back. NOTE: no test links the two. If someone changed the regex in
versionFromIfMatch (or etagFor) the ETag test would still pass. Proposed (not added): a
round-trip test that takes the ETag header from a real GET response and passes it as
If-Match to readCommand, expecting the same version.
