Negative verification NV-173 — the Notes controls move on screen when the history reloads after a post
Method as docs/evidence/R-01_negative_verification.txt, with an E2E case in place of a unit test.

Node        : v24.16.0 (local); Playwright 1.64.0, Chromium project only; Atlas test cluster
Test        : e2e/detail-search.spec.js, E2E-11 (the Record action button's on-screen position
              before posting a comment and after the comment's history entry has appeared)
File broken : client/src/RequestDetail.jsx (never a test); the client was rebuilt after each change

CLAIM
  After a comment is posted, the request and its history are read again and the new entry
  appears above the Notes panel. The page scrolls by the distance the panel moved, so the
  Notes controls stay where they were on screen (and the note buttons are disabled until the
  reload is over). This removes the layout shift behind E2E-11's Firefox failure in run 1.

BREAK
  -     if (Math.abs(moved) > 0.5) window.scrollBy(0, moved);
  +     if (false && Math.abs(moved) > 0.5) window.scrollBy(0, moved);

EXPECTED (written before the run)
  With the break, E2E-11 fails on "the Notes controls moved on screen during the reload",
  by about the height of one history entry. Restored, E2E-11 passes.

FIRST ATTEMPT (18:50:30-18:50:42 UTC broken, 18:50:51-18:51:11 UTC restored), recorded because it
happened: the break failed (moved 57.8 px) but so did the restored code (moved 89.1 px). A probe
showed the baseline was wrong, not the fix: Playwright's click on Post comment scrolled the page
by 85 px before the post, which the test counted as movement; across the reload itself the Notes
panel stayed at the same position. The test now scrolls Post comment into view before taking the
baseline, so the click does not scroll.
