What this shows: a server composed by src/composition.js, connected to the
Atlas test cluster as civicconnect-app, is reachable over HTTP end to end.
The health route is public, the guard refuses a request with no session, and
login sets __Host-sid and stores only its hash. A transition with the
session commits with one history entry. Logout deletes the session, and the
old cookie is then refused.

What this does not show:
- That any index exists on the cluster. Mongoose's automatic createCollection
  and createIndexes would be refused under DEC-003 v0.2's grants (CRUD or
  find+insert only for civicconnect-app). This run did not observe the
  refusal, because Mongoose discards that failure silently. The
  indexes were not inspected in this run and are expected to be absent,
  including the sessions TTL index, unique users.email and the requestHistory
  unique indexes (DEC-015 idempotency, requestVersion). No check above
  depends on an index. The run proves reachability, not that any index exists.
- Transaction atomicity, which needs a fault injected inside the transaction.
- Idle expiry, TLS (Phase 1), load, or the deployed VPS environment.
- Graceful shutdown. The graceful-shutdown path was not exercised, because
  Windows has no SIGTERM and the server was stopped with a forced kill. This is
  not a defect. It is simply not evidenced by this run.
